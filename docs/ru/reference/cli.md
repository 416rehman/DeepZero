## Интерфейс командной строки

CLI `deepzero` — это основной интерфейс для выполнения и управления конвейерами.

```bash
# Стандартное выполнение
deepzero run ./targets -p pipelines/loldrivers/pipeline.yaml

# Проверить авторизацию бэкенда LLM до начала долгого запуска
deepzero run ./targets -p pipelines/source_audit/pipeline.yaml --preflight

# Выполнить с очисткой состояния (новый запуск)
deepzero run ./targets -p pipelines/loldrivers/pipeline.yaml --clean

# Собрать HTML-отчет и открыть его
deepzero report -p loldrivers --open

# Проверить статус выполнения
deepzero status -p loldrivers

# Запустить интерактивную REPL
deepzero interactive -w work/loldrivers

# Запустить REST API Starlette
deepzero serve -w work/loldrivers --port 8420

# Создать новый пользовательский конвейер
deepzero init my_custom_pipeline

# Проверить схему без выполнения
deepzero validate loldrivers

# Список системного реестра
deepzero list-processors
```

`deepzero --version` печатает установленную версию, а `--help` работает и для группы, и для каждой команды.

### Основные команды

| Команда | Описание |
| ------- | -------- |
| `run` | Выполняет конвейер на цели. Автоматически возобновляется, если существует состояние. |
| `report` | Собирает HTML-отчет из результатов запуска. Безопасно выполнять во время самого запуска. |
| `status` | Показывает текущий статус работы конвейера, вердикты и метрики этапов. |
| `validate` | Выполняет тестовую проверку схемы конвейера, импорта процессоров и промптов. |
| `list-processors` | Показывает все встроенные и динамически зарегистрированные типы процессоров. |
| `init` | Создает новую директорию конвейера со стандартным файлом `pipeline.yaml`. |
| `interactive` | Интерактивная REPL на базе LLM для анализа результатов конвейера. |
| `serve` | Запускает сервер REST API для вывода состояния конвейера вовне. |

### `run`

```bash
deepzero run <TARGET> -p <pipeline> [options]
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `TARGET` | требуется | Позиционный аргумент. Путь к анализируемому корпусу. Должен существовать; файл или каталог, смотря что принимает этап приема данного конвейера. |
| `-p, --pipeline` | требуется | Имя конвейера, каталог или путь к отдельному файлу YAML. |
| `-m, --model` | `model` конвейера | Переопределение модели LLM для этого запуска, например `openai/gpt-4o`. |
| `-w, --work-dir` | настройка `work_dir` конвейера | Заменяет корень, под которым строится каталог запуска. |
| `--clean` | выключено | Безвозвратно удаляет данные предыдущего запуска и начинает заново. |
| `--preflight` | выключено | Проверяет, что бэкенд LLM авторизован, до начала работы. Делает один крошечный вызов. |
| `--retry-timeouts` | выключено | Повторяет образцы, у которых вышло время, сохраняя все остальные результаты. |
| `--timeout-multiplier` | `2.0` | Насколько увеличить бюджет при повторе этапа, у которого вышло время. |
| `-v, --verbose` | выключено | Подробное логирование, включая трассировки из кода самого DeepZero. |

Запуск, за которым нет состояния, начинается с нуля; запуск, за которым состояние есть, возобновляется, и заголовок сообщает, какой именно запуск подхвачен. Менять `--model` между запусками разрешено, и это фиксируется: состояние запуска обновляется именем модели, которая будет реально вызываться, поэтому `status` и отчет не описывают модель, которая больше не используется.

`--clean` переименовывает предыдущий каталог в сторону и удаляет его в фоне, чтобы корпус из сотен тысяч файлов не удерживал команду открытой на все время удаления.

#### Где находится состояние запуска

Рабочие каталоги разделены по корпусам:

```text
<work_dir setting>/<pipeline name>/<corpus key>/
```

Ключ корпуса выводится из пути цели: его базовое имя плюс короткий дайджест разрешенного абсолютного пути. Поэтому два корпуса, прошедшие через один конвейер, никогда не делят хранилище образцов, манифест или отчет, и каждый возобновляется независимо. Один и тот же путь всегда дает один и тот же ключ, поэтому повторный запуск возвращается в тот каталог, который покинул.

Флаг `-w, --work-dir` у `run` заменяет только первый сегмент. Сегменты конвейера и корпуса по-прежнему добавляются, потому что именно они разделяют два запуска.

#### Отчет, который запуск пишет по ходу дела

Запуск пишет HTML-отчет в `<work dir>/report` и печатает его URL до начала первого этапа. Отчет перестраивается по мере появления результатов, а не по таймеру, и не чаще раза в 15 секунд, чтобы быстрый этап не тратил время запуска на запись HTML. Он записывается еще раз, когда запуск останавливается, прерван он или завершен, поэтому на диске всегда лежит итоговое состояние.

#### Проверка LLM перед долгим запуском

`--preflight` спрашивает бэкенд, готов ли он, и отказывается стартовать, если нет. Это существует потому, что иначе вы узнаете об этом спустя несколько часов, на первом же этапе оценки, когда дорогие этапы перед ним уже отработали.

Что именно проверяется, зависит от бэкенда, потому что авторизация означает для них разное. Агентский CLI-бэкенд, такой как `claude-code`, отправляет один минимальный промпт, поскольку DeepZero не может прочитать с диска, вошли ли вы в этот бинарник. Бэкенд с ключом API отвечает по результатам проверки ключа, уже сделанной на этапе валидации, и не тратит ничего.

Превышение лимита запросов или сетевая ошибка не считаются отказом авторизации и не блокируют запуск. Проверка включается явно, а не работает всегда, потому что этот единственный промпт представляет собой реальное потребление, каким бы малым оно ни было.

Она выполняется только тогда, когда конвейер задает модель. Конвейеру без этапов LLM проверять нечего.

#### Повтор того, у чего вышло время

Этап, достигший своего `timeout`, записывает образец как исчерпавший время, а не как завершившийся с ошибкой. Это утверждение о бюджете, а не об образце: в него упираются самые крупные образцы, которые в большинстве корпусов и заслуживают внимания, и запись их вместе с настоящими ошибками незаметно уводит запуск в сторону от них.

Возобновленный запуск не повторяет их сам, потому что бюджет, которого не хватило, остался прежним. Попросите об этом явно:

```bash
deepzero run <target> -p <pipeline> --retry-timeouts
```

Забываются только те этапы, у которых вышло время, и им дается в `--timeout-multiplier` раз больше (по умолчанию в 2 раза). Все остальные результаты, полученные запуском, сохраняются, поэтому повтор стоит ровно того времени, которое нужно этим этапам, и ничего сверх. Этапы, не объявившие timeout, не затрагиваются. В отчете они сгруппированы отдельно, с указанием бюджета, который каждый из них превысил.

### `report`

```bash
deepzero report -p <pipeline> [--open]
deepzero report -w work/loldrivers/drivers-1a2b3c4d
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-p, --pipeline` | нет | Имя или путь конвейера. Разрешается в самый недавний корпус этого конвейера. |
| `-w, --work-dir` | нет | Каталог запуска для прямого чтения. Имеет приоритет над `--pipeline`. |
| `-o, --out` | `<work_dir>/report` | Куда записать отчет. |
| `--open` | выключено | Открыть отчет в браузере по завершении. |
| `-v, --verbose` | выключено | Подробное логирование. |

Требуется один из флагов `--pipeline` или `--work-dir`.

Отчет целиком выводится из состояния запуска, поэтому не содержит сведений, которых нет в каталоге запуска. Удалите каталог отчета, выполните команду снова, и вы получите его обратно. Его также безопасно собирать во время запуска: он читает файлы состояния и не пишет ничего, от чего зависит исполнитель, поэтому описывает запуск на момент сборки.

Он записывает:

| Файл | Содержимое |
|------|------|
| `index.html` | Сводка и ранжированный список, ограниченный по размеру |
| `items/<id>.html` | По странице на каждый образец, который стоит прочитать, со ссылками на его артефакты |
| `inventory.csv` | Каждый образец одной строкой, для таблицы |
| `findings.jsonl` | Каждая находка, по одному объекту JSON на строку |
| `report.json` | Только итоговые суммы, для машины |

Образец получает собственную страницу, когда на ней есть что читать: находки, оценка, ошибка или этап, у которого вышло время. Остальные все равно попадают в CSV, а индекс сообщает, когда список был усечен и где искать остаток.

Разрешение по имени конвейера выбирает самый недавний корпус и сообщает об этом, когда конвейер видел больше одного, называя остальные. Самый свежий запуск не всегда тот, о котором спрашивают, и молчаливый ответ про другой корпус представляет собой именно тот сбой, которого стоит избегать. Передайте `--work-dir`, чтобы назвать корпус точно.

Как конвейер называет свои образцы, свои исходы и то, на что он был направлен, берется из блока `report:` конвейера, поэтому `--work-dir` сам по себе рендерит отчет со значениями по умолчанию: блок читается из определения конвейера, а не из каталога запуска. См. [блок report]({{ '/ru/reference/pipeline-yaml.html' | relative_url }}).

### `status`

```bash
deepzero status -p loldrivers
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-p, --pipeline` | нет | Имя или путь конвейера. Разрешается в самый недавний корпус этого конвейера. |
| `-w, --work-dir` | нет | Каталог запуска для прямого чтения. Имеет приоритет над `--pipeline`. |
| `-v, --verbose` | выключено | Подробное логирование. |

Требуется один из двух. Печатает идентификатор запуска, цель, модель, временные метки, таблицу по этапам со счетчиками завершенных, отфильтрованных и сбойных, а также итоги по вердиктам образцов.

### `validate`

```bash
deepzero validate <PIPELINE_REF>
```

Загружает конвейер, разрешает каждый процессор, выполняет собственный `validate()` каждого процессора и проверяет каждый промпт по тем значениям, которые действительно производят предшествующие ему этапы. Флагов не принимает. Выполняйте перед долгим запуском: это самый дешевый способ обнаружить отсутствующий бинарник, нечитаемый набор правил или промпт, запрашивающий то, чего не записывает ни один этап.

### `list-processors`

Печатает каждый зарегистрированный процессор с его типом и реализующим классом. Флагов не принимает. Перечисляются только встроенные: внешний процессор разрешается по своему пути в момент загрузки и не регистрируется под именем.

### `init`

```bash
deepzero init <NAME>
```

Создает `pipelines/<NAME>/pipeline.yaml` в рабочем каталоге с закомментированным скелетом. Существующий каталог не перезаписывает, а отказывается работать.

### `interactive`

```bash
deepzero interactive -w work/loldrivers/drivers-1a2b3c4d
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-m, --model` | `openai/gpt-4o` | Модель для диалога. Любая строка модели, которую принимают бэкенды. |
| `-w, --work-dir` | `work` | Каталог запуска, из которого загружается контекст. |
| `-v, --verbose` | выключено | Подробное логирование. |

REPL, загружающая состояние запуска в системный промпт, чтобы можно было задавать по нему вопросы. Команды `/status`, `/clear`, `/help` и `/quit` обрабатываются локально, все остальное уходит в модель. Обратите внимание, что рабочий каталог по умолчанию буквально равен `work`, а не разрешенному каталогу запуска, поэтому направляйте `-w` на нужный вам запуск.

### `serve` и REST API

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--host` | `127.0.0.1` | Адрес привязки. Все, кроме локальной петли, печатает предупреждение, потому что сервер тогда доступен из сети. |
| `--port` | `8420` | Порт привязки. |
| `-w, --work-dir` | `work` | Рабочий каталог, который обслуживается. |

Требуется дополнительная установка: `pip install deepzero[serve]`.

> [!WARNING]
> **Экспериментальная функция в разработке**
> Сервер REST API в настоящее время не завершен, крайне нестабилен и **не должен использоваться**. Он предоставляется строго для экспериментальной локальной разработки.

Запускает REST API FastAPI/Starlette только на чтение для запросов состояния запуска и данных образцов.

| Конечная точка | Метод | Описание |
|----------|--------|-------------|
| `/api/health` | GET | Проверка работоспособности |
| `/api/runs` | GET | Список доступных запусков конвейеров в рабочем каталоге |
| `/api/run` | GET | Глобальное состояние и метрики текущего запуска |
| `/api/samples` | GET | Список образцов (фильтруется через `?verdict=`, `?stage=`, `?status=`) |
| `/api/samples/{sample_id}` | GET | Полное состояние образца с историческими данными конвейера |
| `/api/samples/{sample_id}/artifacts/{name}` | GET | Чтение конкретного файлового артефакта, созданного процессором |
