## Интерфейс командной строки

CLI `deepzero` — это основной интерфейс для выполнения и управления конвейерами.

```bash
# Стандартное выполнение
deepzero run ./targets -p pipelines/loldrivers/pipeline.yaml

# Проверить авторизацию бэкенда LLM до начала долгого запуска
deepzero run ./targets -p pipelines/source_audit/pipeline.yaml --preflight

# Выполнить с очисткой состояния (новый запуск)
deepzero run ./targets -p pipelines/loldrivers/pipeline.yaml --clean

# Перечислить все запуски на диске, чем бы они ни были получены
deepzero runs

# Собрать HTML-отчет и открыть его
deepzero report -p loldrivers --open

# Проверить статус выполнения
deepzero status -p loldrivers

# Запустить интерактивную REPL
deepzero interactive -w work/loldrivers

# Запустить REST API Starlette
deepzero serve -w work/loldrivers --port 8420

# Создать новый пользовательский конвейер
deepzero init my_custom_pipeline

# Проверить схему без выполнения
deepzero validate loldrivers

# Список системного реестра
deepzero list-processors
```

`deepzero --version` печатает установленную версию, а `--help` работает и для группы, и для каждой команды.

### Основные команды

| Команда | Описание |
| ------- | -------- |
| `run` | Выполняет конвейер на цели. Автоматически возобновляется, если существует состояние. |
| `report` | Собирает HTML-отчет из результатов запуска. Безопасно выполнять во время самого запуска. |
| `runs` | Перечисляет все запуски на диске, каким бы конвейером и корпусом они ни были получены. |
| `status` | Показывает текущий статус работы конвейера, вердикты и метрики этапов. |
| `validate` | Выполняет тестовую проверку схемы конвейера, импорта процессоров и промптов. |
| `list-processors` | Показывает все встроенные и динамически зарегистрированные типы процессоров. |
| `init` | Создает новую директорию конвейера со стандартным файлом `pipeline.yaml`. |
| `interactive` | Интерактивная REPL на базе LLM для анализа результатов конвейера. |
| `serve` | Запускает сервер REST API для вывода состояния конвейера вовне. |

### `run`

```bash
deepzero run <TARGET> -p <pipeline> [options]
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `TARGET` | требуется | Позиционный аргумент. Путь к анализируемому корпусу. Должен существовать; файл или каталог, смотря что принимает этап приема данного конвейера. |
| `-p, --pipeline` | требуется | Имя конвейера, каталог или путь к отдельному файлу YAML. |
| `-m, --model` | `model` конвейера | Переопределение модели LLM для этого запуска, например `openai/gpt-4o`. |
| `-w, --work-dir` | настройка `work_dir` конвейера | Заменяет корень, под которым строится каталог запуска. |
| `--clean` | выключено | Безвозвратно удаляет данные предыдущего запуска и начинает заново. |
| `--refresh` | выключено | Повторяет обнаружение и объединяет текущий корпус с сохраненным запуском. |
| `--preflight` | выключено | Проверяет, что бэкенд LLM авторизован, до начала работы. Делает один крошечный вызов. |
| `--redo` | нет | Заново выполняет названный этап и все, что после него, сохраняя более раннюю работу и удаляя вывод, записанный этими этапами. Флаг можно повторять. |
| `--retry-timeouts` | выключено | Повторяет образцы, у которых вышло время, сохраняя все остальные результаты. |
| `--timeout-multiplier` | `2.0` | Насколько увеличить бюджет при повторе этапа, у которого вышло время. |
| `-v, --verbose` | выключено | Подробное логирование, включая трассировки из кода самого DeepZero. |

Запуск, за которым нет состояния, начинается с нуля; запуск, за которым состояние есть, возобновляется, и заголовок сообщает, какой именно запуск подхвачен. Менять `--model` между запусками разрешено, и это фиксируется: состояние запуска обновляется именем модели, которая будет реально вызываться, поэтому `status` и отчет не описывают модель, которая больше не используется.

`--clean` переименовывает предыдущий каталог в сторону и удаляет его в фоне, чтобы корпус из сотен тысяч файлов не удерживал команду открытой на все время удаления.

#### Обновление обнаруженного корпуса

Возобновление по умолчанию использует сохраненный снимок обнаружения. `--refresh` ищет новые или измененные входные данные по тому же пути. Образцы с неизменными метаданными сохраняют результаты; измененные образцы и их последующие результаты обрабатываются заново. Удаленные из корпуса образцы вместе с артефактами перемещаются в `retired_samples/`. `--redo discover` также повторяет обнаружение во встроенных конвейерах. Проверяются метаданные, записанные процессором ввода, а не любые изменения файлов или сети.

Для манифеста git также задайте `refresh: true` в настройках ввода, чтобы получить новые удаленные коммиты; один `--refresh` лишь перечитает кешированные клоны.

```bash
deepzero run ./drivers -p pipelines/loldrivers/pipeline.yaml --refresh
```

Завершенный запуск возвращает 0, неудачный или прерванный — 1. Ошибки отдельных образцов с политикой `on_failure: skip` остаются в отчете, но не обязательно означают сбой всего запуска.

#### Где находится состояние запуска

Рабочие каталоги разделены по корпусам:

```text
<work_dir setting>/<pipeline name>/<corpus key>/
```

Ключ корпуса выводится из пути цели: его базовое имя плюс короткий дайджест разрешенного абсолютного пути. Поэтому два корпуса, прошедшие через один конвейер, никогда не делят хранилище образцов, манифест или отчет, и каждый возобновляется независимо. Один и тот же путь всегда дает один и тот же ключ, поэтому повторный запуск возвращается в тот каталог, который покинул.

Флаг `-w, --work-dir` у `run` заменяет только первый сегмент. Сегменты конвейера и корпуса по-прежнему добавляются, потому что именно они разделяют два запуска.

#### Отчет, который запуск пишет по ходу дела

Запуск пишет HTML-отчет в `<work dir>/report` и печатает его URL до начала первого этапа. Отчет перестраивается по мере появления результатов, а не по таймеру, и не чаще раза в 15 секунд, чтобы быстрый этап не тратил время запуска на запись HTML. Он записывается еще раз, когда запуск останавливается, прерван он или завершен, поэтому на диске всегда лежит итоговое состояние.

#### Проверка LLM перед долгим запуском

`--preflight` спрашивает бэкенд, готов ли он, и отказывается стартовать, если нет. Это существует потому, что иначе вы узнаете об этом спустя несколько часов, на первом же этапе оценки, когда дорогие этапы перед ним уже отработали.

Что именно проверяется, зависит от бэкенда, потому что авторизация означает для них разное. Агентский CLI-бэкенд, такой как `claude-code`, отправляет один минимальный промпт, поскольку DeepZero не может прочитать с диска, вошли ли вы в этот бинарник. Бэкенд с ключом API отвечает по результатам проверки ключа, уже сделанной на этапе валидации, и не тратит ничего.

Превышение лимита запросов или сетевая ошибка не считаются отказом авторизации и не блокируют запуск. Проверка включается явно, а не работает всегда, потому что этот единственный промпт представляет собой реальное потребление, каким бы малым оно ни было.

Она выполняется только тогда, когда конвейер задает модель. Конвейеру без этапов LLM проверять нечего.

#### Повтор того, у чего вышло время

Этап, достигший своего `timeout`, записывает образец как исчерпавший время, а не как завершившийся с ошибкой. Это утверждение о бюджете, а не об образце: в него упираются самые крупные образцы, которые в большинстве корпусов и заслуживают внимания, и запись их вместе с настоящими ошибками незаметно уводит запуск в сторону от них.

Бюджет ограничивает, сколько ждет этап, а не сколько длится работа. Поток процессора бросают, а не завершают, поэтому запущенный им внешний процесс продолжает работать и после того, как этап пошел дальше. См. [`timeout`]({{ '/ru/reference/pipeline-yaml.html' | relative_url }}).

Возобновленный запуск не повторяет их сам, потому что бюджет, которого не хватило, остался прежним. Попросите об этом явно:

```bash
deepzero run <target> -p <pipeline> --retry-timeouts
```

Забываются только те этапы, у которых вышло время, и им дается в `--timeout-multiplier` раз больше (по умолчанию в 2 раза). Все остальные результаты, полученные запуском, сохраняются, поэтому повтор стоит ровно того времени, которое нужно этим этапам, и ничего сверх. Этапы, не объявившие timeout, не затрагиваются. В отчете они сгруппированы отдельно, с указанием бюджета, который каждый из них превысил.

#### Повторное выполнение одного этапа

Правка промпта, набора правил или конфигурации сканера обесценивает результаты этого этапа и ничего до него. Декомпилировать корпус заново только затем, чтобы задать ему тот же вопрос иначе, стоило бы часов без всякой причины, поэтому назовите этап:

```bash
deepzero run <target> -p <pipeline> --redo assess
```

Каждый образец забывает этот этап и все последующие, а все, что было раньше, сохраняет. Последующие этапы уходят потому, что они потребляли вывод, который вот-вот изменится: оценка, написанная по находкам, которых больше нет, оставила бы один образец описанием сразу двух запусков. Образец, отфильтрованный устаревшим этапом, возвращается в запуск, поэтому суженный набор правил волен прийти о нем к другому вердикту.

Вывод, записанный этими этапами, уходит вместе с состоянием. Несколько процессоров относятся к собственному файлу на диске как к кэшу и подхватывают его вместо того, чтобы делать работу заново, поэтому если забыть только состояние, этап подхватил бы устаревший файл и записал его как свежий, а это хуже, чем не повторять этап вовсе. Поэтому `--redo` удаляет каждый артефакт, записанный сброшенными этапами, и сообщает, сколько файлов убрал. Артефакт, записанный за пределами собственного каталога образца, не трогают, потому что удалять его этому запуску не положено.

`--redo` можно повторять, и отсчет начинается с самого раннего названного этапа. Неизвестное имя этапа отклоняется с перечислением настоящих имен этапов конвейера, а не воспринимается как «нечего делать». Если ни один образец до названных этапов не дошел, команда сообщает об этом и ничего не меняет.

### `report`

```bash
deepzero report -p <pipeline> [--open]
deepzero report -w work/loldrivers/drivers-1a2b3c4d
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-p, --pipeline` | нет | Имя или путь конвейера. Разрешается в самый недавний корпус этого конвейера. |
| `-w, --work-dir` | нет | Каталог запуска или корень конвейера, и тогда читается самый недавний корпус, о чем сообщается. Имеет приоритет над `--pipeline`. |
| `-o, --out` | `<work_dir>/report` | Куда записать отчет. |
| `--open` | выключено | Открыть отчет в браузере по завершении. |
| `-v, --verbose` | выключено | Подробное логирование. |

Ни один из флагов не обязателен. Если даны оба, решает `--work-dir`. Если не дано ни одного, `report` ищет в `work`, а это каталог именно с таким буквальным именем, а не значение настройки `work_dir` конвейера. Единственный найденный там запуск берется и называется. Несколько перечисляются в нумерованной таблице, и в терминале команда спрашивает номер нужного. Вызывающей стороне, которой неоткуда прочитать ответ, показываются тот же список и строка `deepzero report -w <запуск>`, называющая запуск точно, после чего команда выходит с кодом 1, потому что запрос в скрипте его подвесил бы. Полное отсутствие запусков тоже сообщается, и код выхода 1.

Отчет выводится из состояния запуска, поэтому достаточно удалить его каталог и выполнить команду снова, чтобы получить его обратно. Не возвращается только `report/marks.json`: он хранит то, что читатель отметил как проверенное, и это единственное в этом каталоге, чего не может произвести ни один этап. Его также безопасно собирать во время запуска: он читает файлы состояния и не пишет ничего, от чего зависит исполнитель, поэтому описывает запуск на момент сборки.

Он записывает:

| Файл | Содержимое |
|------|------|
| `index.html` | Сводка и ранжированный список, ограниченный по размеру |
| `items/<id>.html` | По странице на каждый образец, который стоит прочитать, со ссылками на его артефакты |
| `inventory.csv` | Каждый образец одной строкой, для таблицы |
| `findings.jsonl` | Каждая находка, по одному объекту JSON на строку |
| `report.json` | Итоговые суммы для машины, вместе со словарем, в котором они названы |

Образец получает собственную страницу, когда на ней есть что читать: находки, оценка, ошибка или этап, у которого вышло время. Остальные все равно попадают в CSV, а индекс сообщает, когда список был усечен и где искать остаток.

Разрешение по имени конвейера выбирает самый недавний корпус и сообщает об этом, когда конвейер видел больше одного, называя остальные. Самый свежий запуск не всегда тот, о котором спрашивают, и молчаливый ответ про другой корпус представляет собой именно тот сбой, которого стоит избегать. Передайте `--work-dir`, чтобы назвать корпус точно.

Как конвейер называет свои образцы, свои исходы и то, на что он был направлен, берется из блока `report:` конвейера, а этот блок живет в определении конвейера, а не в каталоге запуска. `--work-dir` его все равно получает: запуск записывает, каким конвейером он сделан, поэтому блок восстанавливается по имени. Правда, запуск может пережить конвейер, который его породил, и когда тот конвейер больше не загружается, отчет откатывается к формулировкам по умолчанию, а не отказывается собираться. См. [блок report]({{ '/ru/reference/pipeline-yaml.html' | relative_url }}).

### `runs`

```bash
deepzero runs
deepzero runs -w work --open
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-w, --work-dir` | `work` | Корень, в котором искать. Запуском считается любой каталог под ним, содержащий `run.json`, на любой глубине. |
| `--open` | выключено | Собрать отчет самого свежего запуска и открыть его в браузере. |
| `-v, --verbose` | выключено | Подробное логирование. |

Печатает таблицу всех запусков на диске, каким бы конвейером и корпусом они ни были получены, начиная с самых свежих: конвейер, который его записал, каталог корпуса, статус запуска, сколько образцов обнаружил прием, собран ли отчет и когда состояние записывалось в последний раз. Затем печатает строку `deepzero report -w <самый свежий запуск> --open`, чтобы запуск из верхней строки таблицы можно было открыть, не набирая путь целиком.

Ищется файл-маркер `run.json` на любой глубине, а не форма `<рабочий каталог>/<конвейер>/<корпус>/`. Запуск всегда попадает в эту форму, но только относительно собственного корня, а `-w` у `run` волен поместить этот корень куда угодно: поиск по форме отсюда упустил бы каждый запуск, чей корень не совпадает с тем, в котором ищут.

Колонка отчета говорит `built` или `not built`. Это факт о каталоге, а не о результатах: отчет выводится из состояния запуска, поэтому `not built` означает одну команду, а не потерю.

Команда выходит с кодом 1, когда корень не является каталогом, и когда он им является, но не содержит ни одного запуска.

### `status`

```bash
deepzero status -p loldrivers
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-p, --pipeline` | нет | Имя или путь конвейера. Разрешается в самый недавний корпус этого конвейера. |
| `-w, --work-dir` | нет | Каталог запуска или корень конвейера, и тогда читается самый недавний корпус, о чем сообщается. Имеет приоритет над `--pipeline`. |
| `-v, --verbose` | выключено | Подробное логирование. |

Требуется один из двух. Печатает идентификатор запуска, цель, модель, временные метки, таблицу по этапам со счетчиками завершенных, отфильтрованных, сбойных и исчерпавших время, а также итоги по вердиктам образцов. У исчерпавших время своя колонка, чтобы этап, на котором время вышло у всех, не читался как этап, до которого никто не дошел, а это прямо противоположное.

### `validate`

```bash
deepzero validate <PIPELINE_REF>
```

Загружает конвейер, разрешает каждый процессор, выполняет собственный `validate()` каждого процессора и проверяет каждый промпт по тем значениям, которые действительно производят предшествующие ему этапы. Флагов не принимает. Выполняйте перед долгим запуском: это самый дешевый способ обнаружить отсутствующий бинарник, нечитаемый набор правил или промпт, запрашивающий то, чего не записывает ни один этап.

Команда выходит с кодом 1, когда сообщает об ошибке, и с 0 в остальных случаях, поэтому ею можно закрывать коммит. Предупреждения, например о конвейере, не задающем модель, печатаются, но команду не роняют: они описывают конвейер, который запустится, а не тот, который не сможет стартовать.

### `list-processors`

Печатает каждый зарегистрированный процессор с его типом и реализующим классом. Флагов не принимает. Перечисляются только встроенные: внешний процессор разрешается по своему пути в момент загрузки и не регистрируется под именем.

### `init`

```bash
deepzero init <NAME>
```

Создает `pipelines/<NAME>/pipeline.yaml` в рабочем каталоге с закомментированным скелетом. Существующий каталог не перезаписывает, а отказывается работать.

### `interactive`

```bash
deepzero interactive -w work/loldrivers/drivers-1a2b3c4d
```

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `-m, --model` | `claude-code` | Модель для диалога. Любая строка модели, которую принимают бэкенды. |
| `-w, --work-dir` | `work` | Каталог запуска, из которого загружается контекст. |
| `-v, --verbose` | выключено | Подробное логирование. |

REPL, загружающая состояние запуска в системный промпт, чтобы можно было задавать по нему вопросы. Команды `/status`, `/findings [фильтр]`, `/clear`, `/help` и `/quit` обрабатываются локально, все остальное уходит в модель, а нераспознанное `/слово` сообщается, а не оплачивается как реплика диалога. `/findings` перечисляет все находки, записанные запуском, сузив список до строк, совпавших с аргументом, и в том словаре терминов, который объявил написавший этот запуск конвейер.

Флаг `-w` принимает каталог запуска или корень конвейера, называя выбранный корпус, если их больше одного. Значение по умолчанию буквально равно `work`, а это корень над каталогами конвейеров, который не разрешается ни в один запуск; REPL сообщает об этом и отвечает без контекста запуска, а не притворяется, что загрузила его, поэтому направляйте `-w` на нужный вам запуск.

`report` под голым `work` запуск находит, а эта команда нет, и это настоящая разница, а не опечатка в одной из них: `report` ищет каталоги запусков по всему дереву, а `interactive` разрешает один уровень и берет самый недавний корпус под тем, что ему передали. Диалог стоит той определенности, которую дает требование назвать запуск; отчет дешево пересобрать по другому запуску.

### `serve` и REST API

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--host` | `127.0.0.1` | Адрес привязки. Все, кроме локальной петли, печатает предупреждение, потому что сервер тогда доступен из сети. |
| `--port` | `8420` | Порт привязки. |
| `-w, --work-dir` | `work` | Рабочий каталог, который обслуживается. Каталог запуска или корень конвейера, и тогда обслуживается самый недавний корпус, о чем сообщается. |

Требуется дополнительная установка: `pip install deepzero[serve]`, которая приносит Starlette и uvicorn.

> [!WARNING]
> **Экспериментальная функция в разработке**
> Сервер REST API в настоящее время не завершен, крайне нестабилен и **не должен использоваться**. Он предоставляется строго для экспериментальной локальной разработки.

Запускает REST API на Starlette, работающий только на чтение, для запросов состояния запуска и данных образцов. Он обслуживает ровно один запуск, поэтому рабочий каталог разрешается в один корпус до того, как будет напечатан URL, а не после того, как запрос вернется пустым.

| Конечная точка | Метод | Описание |
|----------|--------|-------------|
| `/api/health` | GET | Проверка работоспособности и обслуживаемый рабочий каталог |
| `/api/runs` | GET | Обслуживаемый запуск списком из одного элемента, либо пустой список |
| `/api/run` | GET | Полное состояние этого запуска, либо 404 |
| `/api/samples` | GET | Список образцов (фильтруется через `?verdict=`, `?classification=`, `?stage=`, `?status=`) |
| `/api/samples/{sample_id}` | GET | Полное состояние образца с историческими данными конвейера |
| `/api/samples/{sample_id}/artifacts/{name}` | GET | Чтение конкретного файлового артефакта, созданного процессором |

`verdict` показывает, где образец покинул конвейер, а `classification` то, к чему пришел о нем этап. Оба едут в ответе, поэтому каждый фильтрует то поле, по которому назван. `stage` совпадает с текущим этапом образца; `status` оставляет образец, если этот статус несет любой этап в его истории. Идентификатор образца, содержащий разделитель пути, отклоняется, потому что идентификатор превращается в путь в файловой системе, а этот сервер можно привязать ко всем интерфейсам.
